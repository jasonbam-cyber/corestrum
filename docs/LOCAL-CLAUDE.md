# Local Claude Code connection — macOS preview

Corestrum can run the customer's separately installed, unmodified native Claude Code. Authentication belongs to Claude Code. Corestrum neither implements Claude.ai OAuth nor accepts, reads, exports or proxies subscription tokens. Usage is charged to the customer's plan/provider, subject to that provider's limits. The free Corestrum app does not fund AI.

## Customer flow

1. Install the native macOS CLI from the [official setup page](https://code.claude.com/docs/en/setup). The qualified baseline is 2.1.296; earlier versions are refused. The executable must be in the official native install location (`~/.local/bin/claude`) and carry the verified Anthropic Developer ID signature. Corestrum does not install or update it automatically.
2. In Corestrum, create or unlock the community workspace, then open Connections → Use your local Claude Code → Prepare separate profile. Corestrum checks the binary signature, version and signed-out status before preparing a new profile. It refuses an already authenticated, unprepared profile.
3. Copy the displayed command into Terminal. It contains paths, not credentials. It starts the official interactive binary in a private, separate home/config/work directory with a minimal environment. Complete its own setup and sign-in yourself. All built-in authentication choices remain available; Corestrum does not force a subscription or Console login. Do not paste a subscription token into Corestrum.
4. Exit the CLI, return to Corestrum, Check sign-in, select a model available to your account, confirm you used your own account and connect. Checking status does not ask for AI content. A successful connection does not establish model access or a successful report; the first report is the separate usage test.
5. Choose Your local Claude Code in the agent composer. The business brief accompanies the request. Report tools are disabled; agents draft from supplied material. No external business system is connected by signing in to AI.
6. Disconnect revokes Corestrum's connection and stops its active request. It does not revoke the CLI's login. To sign out, use `/logout` in the same isolated CLI profile. Corestrum does not automatically revoke another application's credentials.

This is a source preview. No customer installation or sign-in has been qualified, and there is no public installer from this change.

## Process and data boundaries

- Mac-native executable discovery is server-owned, not an HTTP-supplied command or PATH search. Each invocation resolves the native install symlink and checks Apple signature validity, identifier `com.anthropic.claude-code`, and publisher team `Q6L2SF6YDW`. The current installed 2.1.296 binary supplied this signature; publisher pin and installation path must be reverified before distribution.
- Every workspace has its own mode-0700 Claude home, configuration, working, temporary and XDG directories. No inherited environment is passed to child processes. This is logical workspace separation, not an OS sandbox against other software running as the same macOS user. Managed machine policy remains authoritative.
- The fresh profile must report signed out and exactly match the expected `configDirectory`. The encrypted vault stores that preparation marker plus the selected model, connection revision and a digest of the account metadata reported by the CLI. No account email or credential is stored there. A metadata change requires reconnection. This is not cryptographic provider identity attestation, and provider metadata completeness differs by auth method.
- CLI credential storage is handled by the unmodified CLI, including its documented Keychain behavior and fallback. Corestrum does not read its credential files or Keychain. Its profile is separate from Corestrum's encrypted vault and must not be included in portable backups as if it were a safe credential export. Native Console profiles have different storage behavior; fresh-profile and method-specific qualification is required. No claim is made that every built-in auth method has been exercised.
- Generation uses restricted/safe mode; no built-in tools, MCP tool calls, Chrome integration, slash commands, session persistence or permission prompts; one turn; 90-second process deadline; 512 KB stdout and 16 KB stderr limits. System instructions are product-owned. Private business input goes through stdin, never command-line arguments. No raw process stderr or auth JSON is returned to the browser or audit ledger. CLI-managed settings can still affect its own behavior; these flags are not an OS sandbox or a claim of zero telemetry/retention by Anthropic.
- Account metadata and the vault connection are checked before and after generation. Sign-out, lock, disconnect or a changed connection discards in-flight results. Lock/disconnect/quit cancel the active process group. Abrupt OS/process failure can leave provider usage uncertain; recovery must retain unknown outcomes without automatically replaying a paid request. Cancellation cannot undo usage already processed upstream.
- Loopback session, origin, CSRF and encrypted-report checks still apply. Optional legacy licensed deployments also verify licenses. No new database schema or cloud credentials. API-key adapters remain separate and reject the local-CLI provider rather than treating subscription tokens as API keys.

## Evidence and release gates

Fixture tests cover missing/unsigned/old CLI, unprepared authenticated profile, wrong configuration, private paths, explicit confirmation, stdin/environment/permission boundaries, account changes, disconnect, cancellation, malformed/oversized responses, two fictional companies and sealed reports. The real subprocess harness tests output bounds and termination. A read-only check of the actual 2.1.296 signed binary found the fresh profile signed out; no login or inference occurred.

Remaining: independent review; customer-owned sign-in/MFA and model access; subscription and each advertised alternative authentication method; actual provider limits/error behavior; signed/notarized app delivery and clean-Mac acceptance; deployment-specific hosted onboarding. Fixture success does not satisfy these gates. No legal agreement was accepted and no paid inference or customer account was used.

Official references checked 2026-10-18: [authentication and separate profiles](https://code.claude.com/docs/en/authentication), [CLI behavior](https://code.claude.com/docs/en/cli-reference), [offering unmodified Claude Code and credential rules](https://code.claude.com/docs/en/legal-and-compliance). The product distribution terms require owner review before release; this work is not that approval.

Rollback: revert this source unit before candidate selection. Existing API-key providers remain usable; disconnect the CLI provider and leave its customer-owned profile intact. Do not delete credential state or sign customers out as an automatic rollback action.
